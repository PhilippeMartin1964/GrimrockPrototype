## Décision technique

Ces readables sont des contenus indépendants, pas des UGridItemDefinitionAsset historiques. Ne pas les effacer sous couvert d'ARM-CLEAN06. Restaurer uniquement les deux pointeurs déplacés, sans inventer de texte, ni modifier le titre/texte override, ItemId, niveau, état, GUID, ou version. L'asset cible doit être exactement sous Tests/Readables, chargé par UE, d'identité non vide et distincte. Le helper compte les chemins anciens complets dans l'archive (ASCII/UTF-16LE), parcourt inventaires actifs/réserve, équipement, curseur, objets monde, réceptacles et pending ; toute divergence entre le nombre d'occurrences et les identités décodées nulles, tout conflit d'identité ou autre identité de lecture pendante dans le fichier à modifier refuse le candidat. L'archive source ne change pas. Deux décodages indépendants et comparaison de toutes les propriétés SaveGame après réparation, puis EncodeChecked et relecture. Un ancien chemin encore présent dans le candidat est refusé. Aucun changement si pas de chemin ancien, octets identiques. Ce contrôle est ciblé, non un analyseur général de sérialisation : les occurrences brutes ne suffisent pas seules. Les tests vérifient les deux vrais assets, le plan atomique, le round-trip de pointeurs restaurés, l'idempotence et le refus de chaînes de texte ambiguës ; les archives réelles ne sont pas couvertes par ces fixtures. Pas de redirecteur permanent ni fallback runtime.
